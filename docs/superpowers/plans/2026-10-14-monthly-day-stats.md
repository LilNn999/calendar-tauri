## 3. 统计口径

### 3.1 数字含义

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 工作日 | 当前月应上班的日期 | 包含周末调休补班，扣除年度安排放假的日期 |
| 休息日 | 当前月不必上班的日期 | 包含周末、调休及法定节假日 |
| 法定节假日 | 法定节日本身落在当前月的日期数 | 是休息日的子集，不能作为第三项再与前两项相加 |
| 本月补班 | 落在当前月的调休上班日期 | 只列当前月，其他月份的关联补班不计入本月 |
| 连休假期 | 年度通知安排的完整放假区间 | 与法定节日日期分开展示，跨月时注明本月占用天数 |

始终满足：`工作日 + 休息日 = 当前月公历总天数`。在数据已收录的年份，还应满足：`法定节假日 <= 休息日`。

例如，2026 年 10 月的预期显示为 **工作日 18 天、休息日 13 天、法定节假日 3 天**；国庆连休安排另外显示 10月1日至7日共7天，本月补班为10月10日（周六）。日期安排依据[2026 年放假通知](https://big5.www.gov.cn/gate/big5/www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，法定节日天数依据[放假办法](https://www.gov.cn/zhengce/content/202411/content_6986380.htm?ddtab=true)。

### 3.2 每天的分类规则

1. 以年度安排中的放假/补班日期为准：安排放假的日期为休息日，安排补班的日期为工作日。
2. 没有年度特殊安排的日期，周六、周日为休息日，周一至周五为工作日。
3. 法定节日日期独立标记，以日期集合去重计数。
4. 月统计只遍历月初至月末，不统计月历网格补齐的上月或下月日期。
5. 日期全部使用本地公历日和 date-fns 处理；避免将 `YYYY-MM-DD` 直接解析为 UTC 日期。

不能根据红色“休”角标、放假区间长度或节日显示名称推断法定天数。2025 年国庆和中秋合并连休、春节跨月、清明/端午恰逢周末等情况，都应使用明确的法定日期。

### 3.3 未收录年份

现有日历可浏览 1900—2100 年，但节假日安排表仅覆盖 2025—2026 年。正式功能必须表达这两个范围的区别。

- 已收录年度：显示确定的工作日、休息日、法定天数和放假/补班安排；无节假的月份可以显示法定节假日 0 天。
- 未收录年度：工作日、休息日仅按周末估算，标签带“估算”；法定节假日显示“—”，不显示 0。
- 未收录年度的说明使用“未收录该年度放假调休安排，仅按周末估算”，也不声称该月没有假期或补班。
- 支持年份由明确的完整年度元数据声明，不能因某一年只存在一条假期规则，就认定已覆盖全年。

## 4. 现有代码与实现方案

### 4.1 数据与月度计算

现有 `src/lib/holidays.ts` 管理放假区间、补班日期、格子角标和说明文字，可直接作为统一来源。需要补充两类信息：

- 为每条 `HolidayRule` 增加必填的 `statutoryDates`，区分法定节日与连休区间；合并假期包含各节日法定日期的并集。
- 为完整年度增加覆盖状态和来源记录；先逐条核对 2025—2026 年。

继续保留 `getHolidayDay()` 的现有接口和角标语义，避免影响 `DayCell`、`PureDayCell` 与 `HolidayBadge`。

新增纯函数文件 `src/lib/monthDayStats.ts`，建议提供 `getMonthDayStats(currentDate)`；在 `holidays.ts` 提供结构化的月份假期信息接口，统一产出法定日期、相交的假期区间与本月补班。函数结果至少包含：

| 字段 | 含义 |
| --- | --- |
| `year` / `month` / `totalDays` | 当前月份与总天数 |
| `workDays` / `restDays` | 当前月工作日、休息日 |
| `statutoryDays` | 法定天数；未收录年度为 `null` |
| `coverage` | 已收录年度或仅周末估算 |
| `holidayPeriods` | 假期名称、完整起止日期、整段天数、本月天数；未收录时明确为未知 |
| `makeupDates` | 当前月补班日期；未收录时明确为未知 |

这些类型是计算结果和展示模型，可就近定义在数据模块中，不属于 SQLite 实体。此方案不需要数据库迁移或新的共享 store。

计算以最多 31 个日期为输入，组件按年/月用 `useMemo` 缓存结果即可。信息窗从结构化数据格式化中文文案，不解析 `tip` 或 `extra` 中的描述文字。

### 4.2 图标与悬浮信息窗

新建 `src/components/calendar/MonthlyDayStatsPopover.tsx`，接收当前浏览月份，内部管理开关、延迟计时器及定位。

- 图标使用已安装的 lucide-react 统计图标，置于年月标题按钮的右侧，作为独立按钮，避免触发“回到今天”或年月选择器。
- 初始图标为次级文字色；悬停/展开时使用主题高亮色及淡色背景。
- 信息窗通过 `createPortal` 挂到 `document.body`，使用 `fixed` 定位；默认位于图标下方，宽度约 328px。
- 测量实际窗高并处理左右、上下空间，窗口不足时翻转或限制高度并滚动；缩放、滚动和调整窗口大小时保持有效定位。
- 图标和信息窗共同管理悬停区域：进入约 140ms 后展开，离开约 180ms 后收起，移入窗内取消收起计时器。
- 点击和键盘聚焦也可打开；Escape、外部点击及焦点离开均可关闭。鼠标移开不应破坏仍在窗内的键盘阅读。
- 关闭后不得因焦点恢复立即重新打开；组件卸载时清除全部计时器、监听器与观察器。
- 当前月份或视图切换时关闭旧信息窗，再按新月份计算；页面切换或组件卸载后不留下旧浮层。
- 使用真实按钮及准确的可访问名称；根据内容是否包含交互，选择对应的非模态信息窗语义，并同步 `aria-expanded` 和关联关系。
- 复用主题表面、文字、边框、阴影和休/班颜色令牌，不写固定颜色值。

现有 `HolidayBadge` 已采用 Portal，可参考其避裁切思路，但不能直接复用其 `pointer-events-none` 行为。`src/components/ui/popover.tsx` 是点击打开、带遮罩的自定义实现；本次将悬停行为集中在新日历组件中，避免改动通用 UI 生成物。

### 4.3 主界面接入

在 `src/components/calendar/CalendarHeader.tsx` 引入新组件，将年月标题和统计按钮放在同一行的独立兄弟元素中。

- 显示条件：`calendarMode || viewMode === 'month'`。
- 当前月份来源：`useCalendarStore.currentDate`。
- 普通月视图与纯日历模式使用同一组件、同一统计函数。
- 年月选择器打开时关闭统计窗；统计窗打开时关闭年月选择器，避免两个浮层重叠。
- 项目切换、任务筛选、右侧栏展开/折叠不改变统计口径。

本功能的状态属于局部展示状态，继续使用组件内部状态。任务完成、子任务、打卡、备注和数据库操作不参与这些天数的计算。

### 7.3 桌面与发布约定

前端构建成功只说明前端验证通过。用户启动桌面测试时，必须使用 `启动测试窗口.bat` 的自动检测流程，由脚本在需要时执行 `npm run tauri build -- --no-bundle` 后启动最新版本；禁止把旧 release exe 当作已更新的测试版。

测试始终使用 `CALENDAR_TEST_MODE=1` 与 `test-calendar.db`。代理不自动启动测试窗口或安装包；桌面操作由用户自行完成。本次文档记录不表示桌面测试或发布已经完成。

后续进入正式安装包交付时，再按 `AGENTS.md` 与 `docs/build-notes.md` 的规则执行 `npm run tauri build`，交付根目录 `安装包/` 下的原名产物，报告大小与 SHA256，并记录构建信息、数据排除检查和 NSIS 模板差异核对。

## 8. 数据维护与后续增强

新增年份时同时追加完整年度放假区间、补班日期、法定日期、来源及覆盖标记，并补充代表月份的回归用例；年度通知发布前维持未收录提示。应用运行时直接读取随版本发布的静态数据。

可以在首版后独立评估：点击统计项高亮对应日期、周视图中的月份统计入口、自定义单休/轮班口径。日期高亮若实施，应由共享日期分类提供结果，并分别核对普通月历和纯日历格子，不改任务完成状态。
