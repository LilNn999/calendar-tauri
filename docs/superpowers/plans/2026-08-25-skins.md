# 日历皮肤系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留现有功能和布局的前提下，新增 5 款皮肤、修复日历三态视觉，并让皮肤与明暗模式通过顶部衣服图标入口同步到主窗口和悬浮窗。

**Architecture:** 使用 CSS 变量皮肤层；`ThemeProvider` 扩展 `skin` 状态并持久化；新增纯函数负责皮肤归一化和日历状态优先级；新增 `SkinSwitcher` 弹层承载显示模式与皮肤选择。

**Tech Stack:** React 19、TypeScript、Tailwind CSS v4、Zustand、Tauri v2、Node 内置 test runner。

**Spec:** `docs/superpowers/specs/2026-08-25-skins-design.md`

## Global Constraints

- 不增加 npm 依赖。
- 不改变现有业务逻辑与主体布局。
- 中文 UI 文案。
- 不执行 git commit（仓库开发规范）。
- 最终必须通过 `npm run build`。

### Task 3: ThemeProvider 皮肤状态

**Files:**
- Modify: `src/lib/theme.tsx`

**Interfaces:**
- ThemeContext 新增：`skin: Skin`、`setSkin: (skin: Skin) => void`
- `applyClass(theme)` 保持明暗 class
- 新增 `applySkinClass(skin)`：移除全部 `skin-*`，再添加合法皮肤 class

**实现：**
- 初始化从 `localStorage` 获取 `skin`，Tauri 再从 `systemApi.getSkin()` 校准。
- `setSkin` 写 localStorage、调用 `systemApi.setSkin`、发送 `PUSH_SKIN_CHANGED`。
- 监听 `PUSH_SKIN_CHANGED`，用 `normalizeSkin` 校验后更新。

- [ ] **Step 1:** 实现 ThemeProvider 扩展。
- [ ] **Step 2:** `npm run build` 暂不要求，但 `tsc -b` 应无皮肤相关类型错误。
